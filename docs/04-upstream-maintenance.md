# 上游更新适配与防失效（任务 5）

## 版本检测发生的阶段

本方案是**独立构建**：所有兼容性判断都在构建/探测阶段完成，构建出的二进制
与其内嵌插件、网页资源天然一致。它不会也不能改变系统 `/usr/bin/zellij`
的运行时行为；系统安装始终是安全的回退。

| 阶段 | 命令 | 检测内容 | 失败行为 |
| --- | --- | --- | --- |
| 构建前 | `tools/zhcn.py check` | 工作区 HEAD == 基线提交；补丁可顺序干净应用（临时索引上 `git apply`）；译文目录合法 | 退出非零并拒绝构建，中文说明恢复步骤 |
| 构建 | `tools/zhcn.py build` | check + apply；`cargo xtask ci build-release` | 补丁冲突/编译失败即中止，不产出二进制 |
| 周期检测 | `tools/zhcn.py upstream-status` | `git ls-remote --tags` 列出 ≥ 基线的新标签 | 只报告，不自动适配 |
| 适配探测 | `tools/zhcn.py probe --tag vX.Y.Z` | 克隆目标标签；逐补丁 `git apply --check`；补丁触及文件是否被上游删除；zellij-tile 等接口 crate 版本差异；界面文字候选差异（启发式） | 有补丁失败或文件缺失 → 退出码 2，结论"未适配"；报告写入 `.work/probe-<tag>/PROBE-REPORT.json` |
| 译文核对 | `tools/zhcn.py report` | 补丁树中 `tr()/tr_ctx()/trf()/t()`/配置标签的键与目录对比：缺译、未使用、占位符不一致 | 占位符不一致 → 非零退出；缺译仅警告（运行时回退英文）；`--strict` 下缺译/冗余也非零（CI 使用）。需要已应用补丁的工作区 |

探测结果只会被报告或用于生成待审改动；不会自动改 `upstream.toml`，
不会自动构建，更不会触碰用户安装。未经验证的新版本标记为"未适配"。

## 升级演练记录

演练对象：v0.45.1（明确的不同上游版本，`git ls-remote` 证实存在）。

- 命令：`python3 tools/zhcn.py probe --tag v0.45.1`
- 结果（演练时补丁队列为 17 个）：退出码 2；15/17 补丁失败；52 个文件缺失；插件 crate 布局变化
  （v0.45.1 将 `status-bar`/`tab-bar`/`compact-bar` 分为独立插件，v0.46.0 合并为 `bars`）。
- 结论：不兼容被**发现**而不是静默失败；工具拒绝把该版本标记为受支持；
  系统安装与已构建的二进制不受影响。

这是对"v0.45.1 这一真实上游版本"的探测结论，不代表其它版本的兼容性。

## 防失效的回退设计

- 补丁用 `tr("English")` 包装英文原文，原文即译文键：上游改动这段文字时，
  要么补丁应用失败（构建被阻断，早发现），要么译文键在目录中查不到而
  **原样显示英文**（可用，不空白、不错位）。
- 上游新增文字同理自动回退英文；`probe` 的候选差异清单提示哪些新文字
  可能需要补译（启发式，需人工盘点，不虚报覆盖率）。
- `export-patches` 拒绝把构建产物（`*.wasm`、`app.js` 等再生成文件）混入补丁。
- 每次构建在二进制旁写 `zellij.zh-buildinfo.json`：上游版本/提交、
  每个补丁的 SHA-256、目录哈希、工具哈希与构建时间，用于核对与汇报。

## 人工盘点清单（无法自动覆盖的部分）

- 截图/布局验证（宽度、截断、点击区域）只能人工或脚本抽查，probe 不验证。
- `collect_candidates` 是启发式：会误报（配置键、内部字符串）也会漏报
  （拼接生成的文字、多行字符串）。
- 上下文菜单标签来自 `default.kdl`；上游改默认标签时 probe 的候选差异
  会显示，但用户自定义标签无法枚举。
- 插件 wasm 与宿主之间的 IPC 兼容性在版本混用时无法自动验证——
  本方案不混用（二进制内嵌构建），故风险为零，但若将来支持系统二进制
  加载汉化插件，需另行验证。

## CI

`.github/workflows/zh-cn-ci.yml`：

- `check` 作业（push/PR）：工具单元测试 + `check` + `cargo test`（zellij-i18n）。
  补丁无法应用或目录非法时失败 → 不产生任何发布物。
- `build` 作业（push/PR）：`tools/zhcn.py build` 完整构建，随后 `report --strict`
  （补丁树中的键与译文目录必须完全对应），产出二进制与 buildinfo 作为
  artifact（仅构建产物，不发布、不部署）。
- 注：CI 配置尚未在 GitHub 上实际运行过，首次 push 后需要观察并修正。
- `upstream-watch` 作业（每周定时）：`upstream-status` 列出新标签；若存在
  未适配标签则 `probe` 最新一个并把 `PROBE-REPORT.json` 作为 artifact，
  供人工评审后再决定是否适配。失败不会自动标记任何版本为受支持。
